## Overview

Strategic plan for maturing nodus from an in-tree vendored crate to an independently extractable, production-ready workflow-language library. The arc runs: spec completeness → library hardening → extraction readiness → observability & extension framework → portability → testing → capability manifest (LP-8). Each new contract spec is implemented, then its L2 spec is synced to the realized Rust shape.

Execution mode: **Sequential** (spec correctness must precede hardening; hardening must precede extraction).

> **Scope note.** Per §4.1's own structural argument, dispatch fires once per **top-level** step, using `ctx.errors.last()` if the step is itself a `~FOR`/`~UNTIL`/`~PARALLEL` construct whose body produced one or more errors during its own internal iteration — not once per inner iteration. That fixture's declared assertion has therefore never actually been evaluated — a latent correctness defect independent of any round-tripping concern, and arguably the more urgent half of this cluster.
    3. **Quoting information is destroyed at lex time and is unrecoverable from the AST.** The lexer strips quotes before `raw_lines` is built, so `"T-001"` is stored as `T-001` and re-lexes as two tokens (`T`, `-001`) — exactly the corruption the harness observed. **This is what makes the item spec-shaped rather than code-shaped: no emitter-only change can restore NL-6 AST-equality, because the information needed to reconstruct re-parseable source is in neither `raw_lines` nor the structured fields.**
