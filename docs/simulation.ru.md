# Симуляция использования

Практическое руководство по `cronus-sim`: харнесс, который ведёт реальный бинарь
`cronus` к заявленной цели так же, как это делал бы настоящий новичок или
вернувшийся пользователь — никогда не проигрывая заранее написанный скрипт.

## Зачем это существует, в одном абзаце

Сценарий называет *кто чего хочет и что ему разрешено знать* — но никогда не то,
какие команды набирать. Что-то (сегодня — агент, позже — человек) ведёт реальный
продукт к этой цели любым маршрутом, который найдёт, потому что маршруты, которые
никто не догадался прописать в скрипте, — это как раз то, за чем стоит наблюдать.
Любой вердикт, который выносит этот харнесс — pass, fail или «ещё открыто», —
решается против небольшого явного набора обязательств (obligations), которые
сценарий объявляет заранее, а не против транскрипта, который кто-то просматривает
глазами постфактум.

Файлы сценариев лежат в [`simulations/`](../simulations/); их формат (поля
frontmatter, уровни vantage, классы возмущений, чек-лист автора) описан в
[`simulations/README.md`](../simulations/README.md). Это руководство — про
другую половину: саму команду `cronus-sim` и когда к ней обращаться.

## Сборка

```powershell
cargo build -p cronus-cli --bin cronus          # тестируемый продукт
cargo build -p cronus-simulation --bin cronus-sim
```

Оба бинарника оказываются в `target/debug/` (или `target/release/` с
`--release`). `cronus-sim` находит `cronus` сам, поднимаясь вверх от каталога
собственного исполняемого файла — не нужен ни флаг `--bin`, ни настройка `PATH`,
если оба собраны обычным способом. Переопределить путь явно можно через
`--bin <path>` (принимают `world new` и `coverage`), либо через переменную
окружения `CRONUS_SIM_BIN_CRONUS=<path>`.

## Базовые понятия

| Термин | Значение |
| --- | --- |
| **World (мир)** | Одноразовый, изолированный рабочий каталог, внутри которого выполняется продукт. Строится заново под каждый сценарий, уничтожается по `finish`. Никогда не касается настоящего чекаута репозитория — прогон, который каким-то образом всё же его затронул, помечается `contaminated`, а не оценивается по своим собственным критериям. |
| **Bound (граница)** | Три независимых потолка, которые объявляет сценарий: `steps` (сколько вызовов `run` разрешено), `wall_secs` (сколько реального времени может пройти), `spend_usd` (сколько может потратить *сам ведущий агент* на исследование). Превышение любого из трёх отказывает в следующем `run` — механизм, который останавливает застрявшего актора от неограниченной траты ресурсов на цель, которую продукт не может удовлетворить. |
| **Obligation (обязательство)** | Утверждение о состоянии мира, которое должно выполняться к концу прогона — решается человеком или агентом, смотрящим на транскрипт, записывается через `verdict`, никогда не выводится автоматически. Набор обязательств, который в принципе не может провалиться (пустой, расплывчатый, описывающий действие вместо исхода), отклоняется уже при загрузке файла сценария. |
| **Note (заметка)** | Произвольная текстовая находка, записывается через `note`. Никогда не влияет на вычисленный исход — это информация, а не проверка. |
| **Outcome (исход)** | То, что сообщает `finish`: `pass`, `fail`, `incomplete` (какому-то обязательству так и не вынесли вердикт), `contaminated` (реальный репозиторий был испачкан посреди прогона), `environment`/`void` (сам харнесс не смог аккуратно снести мир — никогда не вменяется продукту). |
| **Replay case (кейс воспроизведения)** | Транскрипт, который `pin` дистиллирует в закоммиченный `.toml`-файл под `crates/simulation/tests/replays/`. Выполняется детерминированно, без агента и без чьего-либо суждения, в рамках обычного гейта `cargo test` — дешёвая, постоянная защита, которую покупает одноразовая находка, once она сделана. |

## Справочник команд

| Команда | Что делает |
| --- | --- |
| `cronus-sim world new [--bin <path>] <scenario-file>` | Парсит и валидирует сценарий, строит свежий мир, печатает id мира. |
| `cronus-sim run <world-id> -- <argv...>` | Запускает `cronus <argv...>` внутри мира, печатает его stdout/stderr, записывает код возврата. Отказывает, если исчерпана любая из границ. |
| `cronus-sim note <world-id> <text...>` | Записывает находку. Всегда успешен; никогда не оценивается. |
| `cronus-sim spend <world-id> <usd>` | Сообщает о собственных инкрементальных расходах ведущего агента с момента его последнего отчёта (его собственный расход токенов, а не то, что способен измерить сам продукт). Всегда успешен, даже сверх границы — отказ проявляется на *следующем* `run`, точно так же, как граница по времени обнаруживается пассивно. |
| `cronus-sim verdict <world-id> <obligation-id> <pass\|fail> [--cite i,j,...]` | Записывает вердикт по одному объявленному обязательству, опционально ссылаясь на индексы записей транскрипта как на доказательство. |
| `cronus-sim finish <world-id>` | Вычисляет исход, сносит мир, печатает отчёт. Код возврата кодирует исход (см. ниже). |
| `cronus-sim pin <world-id> <name>` | Дистиллирует каждую записанную запись `run` в `crates/simulation/tests/replays/<name>.toml`. **Должна запускаться до `finish`** — `finish` удаляет мир, а `pin` нужно, чтобы он ещё существовал. |
| `cronus-sim coverage [--bin <path>]` | Печатает полный каталог действий продукта, какую его часть покрывают декларации `covers` корпуса сценариев, и — собственно главное — список того, что пока не покрыто ничем. Никогда не проценты: голые «60%» схлопывают «60% от шести» и «60% от ста» в одинаково выглядящее число, с которым никто ничего сделать не может. |

Код возврата `finish`: `0` pass, `1` fail, `2` incomplete, `3` contaminated,
`4` void, `5` ошибка использования самого `cronus-sim`, `6` `run` отклонён
из-за исчерпанной границы.

## Полный разобранный прогон

Ведём единственный сценарий, уже лежащий в корпусе,
[`simulations/short/first-run-three-cards.md`](../simulations/short/first-run-three-cards.md):
новичок, не читавший ничего, кроме `--help`, жонглирует тремя карточками,
откладывает одну в сторону, не теряя её, и позже возвращается, чтобы найти всё
таким, каким оставил. Ниже — настоящий прогон, сохранённый ровно так, как он и
произошёл, включая неверные повороты — потому что неверные повороты и есть вся
причина, по которой этот харнесс существует вместо фиксированного скрипта.

```bash
WID=$(cronus-sim world new simulations/short/first-run-three-cards.md)

# Три вещи, за которыми надо следить.
cronus-sim run "$WID" -- board add card-1 "write the proposal"
cronus-sim run "$WID" -- board add card-2 "review the budget"
cronus-sim run "$WID" -- board add card-3 "call the vendor"
cronus-sim run "$WID" -- board list        # все три стартуют в `triage`
```

Работаем над самой важной. `board move --help` перечисляет все пять состояний
(`triage|todo|ready|running|blocked|done`) как равно допустимые цели — ничто в
нём не говорит, что они образуют упорядоченную цепочку:

```bash
cronus-sim run "$WID" -- board move card-1 running
```

```text
error: invalid transition: Triage → Running (from Triage, only Todo is allowed)
```

Настоящая находка с первой же реальной попытки — записываем её, затем ищем
настоящую цепочку, пробуя следующий шаг, который подразумевал `--help`:

```bash
cronus-sim note "$WID" "board move --help lists all five states as valid targets but never discloses the allowed order; triage->running is refused, discoverable only by trying"
cronus-sim run "$WID" -- board move card-1 todo      # ok
cronus-sim run "$WID" -- board move card-1 ready      # ok
cronus-sim run "$WID" -- board move card-1 running    # ok — настоящая цепочка: triage->todo->ready->running
```

Теперь собственный «reversal» сценария: card-1 только что переведена в активную
работу, и персонаж передумывает и возвращает её назад. Прямая цепочка
подсказывает, что шаг назад — это `ready` — что тоже оказывается неверным:

```bash
cronus-sim run "$WID" -- board move card-1 ready
```

```text
error: invalid transition: Running → Ready (from Running, only Todo, Blocked, Done are allowed)
```

```bash
cronus-sim note "$WID" "the chain is asymmetric: Running steps back to Todo (skipping Ready), not to Ready — the 'undo one step' intuition the forward chain suggests does not hold in reverse"
cronus-sim run "$WID" -- board move card-1 todo       # настоящий путь назад
```

Откладываем третью карточку в сторону, не теряя её. `board block --help`
говорит только «Block a card with a reason» — ничего о том, какие состояния он
принимает:

```bash
cronus-sim run "$WID" -- board block card-3 "not needed right now"
```

```text
error: invalid transition: Triage → Blocked (from Triage, only Todo is allowed)
```

Следуя той же прямой цепочке, которую только что выучили — и обнаруживая, что
она не останавливается там, где остановилась бы разумная догадка:

```bash
cronus-sim run "$WID" -- board move card-3 todo
cronus-sim run "$WID" -- board block card-3 "not needed right now"   # всё ещё отказ: Todo допускает только Triage, Ready
cronus-sim run "$WID" -- board move card-3 ready
cronus-sim run "$WID" -- board move card-3 running
cronus-sim run "$WID" -- board block card-3 "not needed right now"   # ok — Blocked достижим только из Running
```

```bash
cronus-sim note "$WID" "MAJOR: Blocked is reachable only from Running — a card must be promoted through the whole todo->ready->running chain before it can be set aside at all; there is no way to block a card the persona has merely written down and never started"
```

Проверяем, что осталось видно, делаем что-то другое, затем возвращаемся позже и
убеждаемся, что ничего не сдвинулось само по себе:

```bash
cronus-sim run "$WID" -- board show card-2
cronus-sim run "$WID" -- board list
```

```text
id: card-1, state: todo
id: card-2, state: triage
id: card-3, state: blocked
```

Обе всё ещё активные карточки видны, а отложенная по-прежнему числится в списке
со своим реальным состоянием, а не исчезла — судим каждое объявленное
обязательство ровно по этому выводу, сообщаем о собственных расходах агента на
исследование, **фиксируем маршрут до завершения** (`finish` удаляет мир, так
что маршрут можно заморозить только пока он ещё существует), затем закрываем
мир:

```bash
cronus-sim spend "$WID" 0.06

cronus-sim verdict "$WID" the-two-still-tracked-are-visible pass --cite 19
cronus-sim verdict "$WID" the-set-aside-item-is-not-silently-gone pass --cite 19
cronus-sim verdict "$WID" no-silent-failure pass --cite 4,6,9,13

cronus-sim pin "$WID" three-cards-block-only-from-running

cronus-sim finish "$WID"
```

Обязательства проходят — ничто здесь не пропало, и каждый отказ назвал свою
причину — но прогон всё равно выявил реальное поведение продукта, достойное
чьего-то внимания: ещё не начатую карточку нельзя отложить напрямую, только
после того, как её протолкнули до самого `running`. Это ровно тот тип находки,
который фиксированный тестовый скрипт, исполняющий только тот маршрут, что уже
держал в голове его автор, произвести не может. Зафиксированный файл теперь
запускается детерминированно каждый раз, когда кто-то выполняет
`cargo test -p cronus-simulation` — в момент, когда это поведение когда-либо
изменится, этот тест упадёт и объяснит почему.

## Когда что запускать

Свободный маршрут исследования по замыслу стоит агенту собственного времени и
денег — эта непредсказуемость и есть весь смысл, и именно поэтому ей не место в
автоматическом гейте. В нём место только её замороженному остатку
(зафиксированному replay).

| Слой | Стоимость | Запускать… | …где |
| --- | --- | --- | --- |
| Зафиксированные replay (`crates/simulation/tests/replays/*.toml`) | детерминированно, секунды | при каждом изменении | обычный `cargo test`, уже подключено |
| Валидация файлов сценариев (`crates/simulation/tests/corpus.rs`) | детерминированно, секунды | при каждом изменении | обычный `cargo test`, уже подключено |
| `cronus-sim coverage` | секунды | при закрытии этапа работы, перед вырезкой релиза | вручную, читать как отчёт — никогда не как гейт |
| `simulations/short/` | агент в цикле, минуты | сразу после закрытия этапа работы, перед планированием следующего — единственное окно, где свежая находка ещё может изменить то, что будет запланировано дальше | вручную |
| `simulations/broad/` | больше ходов, больше стоимость | перед вехой или релиз-кандидатом | вручную |
| `simulations/exhaustive/` | самый дорогой уровень | по требованию, перед крупным релизом | вручную |

Никогда не встраивайте свободно-маршрутное исследование в CI. Агент, ведущий к
цели любым найденным маршрутом, по построению невоспроизводим от запуска к
запуску и сжигает реальные токены — поместить это в пайплайн значило бы силой
превратить это в фиксированный скрипт, чем сценарий по определению быть не
должен.

## Уборка

Файлы мира живут в системном временном каталоге (`%TEMP%`/`$TMPDIR`), под
именем `cronus-sim-world-<id>` — никогда внутри чекаута репозитория; харнесс
активно отказывается строить мир там. `finish` удаляет каталог как часть сноса
мира. Мир, брошенный посреди прогона без вызова `finish` (упавший агент,
убитый процесс), просто оставляет свой каталог позади — безопасно удалить
вручную, и безвредно оставить как есть, поскольку ничто за пределами
временного каталога от него никогда не зависит.

## Известные ограничения

- `spend_usd` — это бюджет на расходы *самого ведущего агента*, а не на что-либо,
  что делает сам продукт — здесь пока ничто не вычисляет денежную сумму
  автоматически. Пока шаг сценария не включает реальный вызов модели, `spend`
  приходится сообщать вручную (или тому, что оркестрирует агента).
- Coverage вычисляется из вывода shell-completion самого продукта, который
  сегодня перечисляет только действия CLI. Сценарий, задействующий терминальный
  интерфейс или desktop-оболочку, всё равно выполняется и всё равно оценивается —
  он просто не попадает в счётчик каталога `coverage`.
